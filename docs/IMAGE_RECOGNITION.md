# 本地截图识别

## 已实现流水线

选择图片 / 相册 / 拍照、拖拽、粘贴（含多张） → 浏览器原生解码与方向处理 → 大图缩小 → 自动找规则网格 → 用户调整框选和尺寸 → 切格 → 模板与颜色特征 → 可选 OCR → 可编辑草稿 → 用户核对 → 加入房间与求解。

PNG/JPEG 读取头部尺寸，尽早拒绝超过 2000 万像素的图片；其他格式依赖原生解码，并在解码后检查像素。最多 30MB、最长边缩放至 1600px，一次只处理一张。HEIC/HEIF 是否可解码依赖浏览器；失败时提示转为 PNG/JPEG/WebP。原生解码处理 EXIF 方向，但没有手工透视矫正。

## 定位与分类

定位采用 RGB 边缘投影，在各轴寻找等间距线段，并验证横纵间距与方形范围；对边界外仍有网格线的候选扣分，避免截取大棋盘的 8×8 子区。自动识别 8/10/12，用户始终可以改尺寸和四个裁剪滑块。没有足够边缘证据时明确提示手动框选。

格子切割排除约 13% 边缘。以边缘像素中位数估算当前格子的背景，提取相对背景差异的前景，归一化成 20×28 二值形状。参考模板由当前设备系统字体 Arial/Verdana/Tahoma/Georgia/system-ui 的常规与粗体 0–8 生成，另含 ✓、✔、⚑ 符号候选，不来自原站或游戏专有资源。

数字通过 Jaccard 重叠度和最佳/次佳类别差值决定是否接受；较大的青色区域作为宝石候选，符号可提出安全或旗标候选。宝石/符号结果仍要求人工核对。模板不确定而有明显前景的格子才进入 Tesseract 单字符模式，白名单 0–8；低于 80% OCR 置信度时保持未知。

通用系统字体不是游戏字体模板。当前配色和外形规则是透明可修改的候选识别方案，并未根据真实游戏截图校准。纯色空白可能代表未翻开或空格，故保守地保持未知，不自动填 0 或安全。

## 校正与失败处理

橙色虚线边框表示需要核对；点击可改数字、宝石、安全或旗标。显示低置信度数量，整张棋盘必须勾选核对才导入；未能识别的位置仍是未知变量。自动校验由正式 solver 执行，冲突线索会高亮并提示修改，不伪造有效概率。

取消终止图像 worker 与 OCR 工作，保留已经显示的人工修正；重复识别同一尺寸和图片时保留人工校正格子。换图片/尺寸建立新草稿。OCR 资源无法加载时继续模板识别并提示降级，已有草稿可继续手动校正。

## 资源与隐私

Tesseract [官方 API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)支持独立 workerPath/corePath/langPath。本项目显式设置为部署路径下的 `ocr/`，postinstall 将 npm 包的 worker、WASM、eng.traineddata.gz 复制到 public。模型和代码是同源静态读取，图片从不上传。需将完整 OCR 目录随 dist 部署，不依赖临时 CDN URL。

一般环境运行图像 worker，OCR 另有后台 worker；缺少 OffscreenCanvas 时回退到分格 Canvas 操作与事件循环让步。未知且模板不确定的格子较多时 OCR 可能耗时，应使用进度和取消按钮。

## 验证素材与扩展

`tests/fixtures/` 仅有自制规则棋盘、独立数字和不确定文字图片，不是游戏截图。已验证三种尺寸的规则网格定位、宝石候选、数字模板、模糊图片降级、格式/尺寸防护、真实 Tesseract 数字 5、确认导入、多图和取消。

后续真实素材建议按设备/主题/分辨率建立 `tests/fixtures/real/`，配套 JSON 指定原图坐标、尺寸和每格 ground truth；通过同一 detectGrid/cropPixels/classifyCell/recognizeCells 接口测误检与漏检，再增加授权游戏数字模板和宝石特征。不要以合成图片的通过率宣称真实游戏识别率。
