# 本地截图识别

## 自动流水线

电脑直接上传；手机选择相册或拍照，另支持拖拽、粘贴及多图 → 原生解码与方向处理 → 大图缩小 → 自动定位及判断 8/10/12 → 切格 → 字体模板/颜色特征 → 数字 OCR 回退 → 高置信度结果填入新房间 → 自动关闭进度弹窗并求解。

不提供尺寸、裁剪参数或开始按钮。低置信度结果以候选元数据保存在主棋盘，真实观察保持未知，不参与约束。点击带问号/虚线的格子，在宝石和 0–8 弹窗中确认，才转换成真实线索。可用擦除工具撤回记录。

PNG/JPEG 先读头部尺寸，拒绝超过 2000 万像素；其他格式原生解码后检查像素。最多 30MB、最长边缩放至 1600px，最多 20 张逐张处理。HEIC/HEIF 依赖浏览器解码能力；失败时提示转为 PNG/JPEG/WebP。原生解码处理 EXIF 方向，尚未实现透视校正。

## 定位与分类

RGB 边缘投影寻找等间距横纵线，验证间距、方形范围和尺寸；边界外仍有网格线时扣分，避免把大棋盘子区域误认为 8×8。自动定位置信度低于 0.72 时拒绝导入，提示提供完整清晰棋盘；不把图例、裁切图当成棋盘。

切割排除约 13% 边缘，以边缘像素中位数估算格子背景，再提取前景并归一化成 20×28 二值形状。参考模板由当前设备系统字体 Arial/Verdana/Tahoma/Georgia/system-ui 的常规/粗体及 30/42/54px 多字号生成，覆盖 0–8，并含 ✓/✔/⚑ 候选。多字号减小不同浏览器与小字抗锯齿造成的形状差异，未复制原站资源。

数字匹配检查 Jaccard 重叠度与次佳类别差；青色大区域提出宝石候选，符号提出安全/旗标候选。有前景但模板无法判断的格子使用 Tesseract 单字符 OCR，白名单 0–8。OCR 小于 80% 不采纳；自动填入事实的统一门槛为 90%，80–90% 的数字仍待核对。置信度是识别分数，不是经真实素材校准的准确率。

青色宝石规则目前只能提出低置信度候选（0.7），不会自动声明真实发现。空白没有足够证据区分未翻开与安全，保留未知，不自动填 0。系统字体不是游戏专有字体，真实游戏宝石与数字仍需样本校准。

## 失败与取消

定位失败、损坏图片、格式不支持会保留原房间并明确提示重新上传。识别过程中可以取消；终止 worker/OCR，保留原数据和本次队列中已经导入的房间。OCR 资源加载失败时继续模板识别，不确定位置保留候选供手动修改。

新房间默认宝石数按尺寸为 20/30/45；截图目前不读取房间号和总宝石数字，主页面可调整。正式 solver 校验线索，矛盾会高亮并提示，不输出伪造概率。

## 资源与隐私

OCR worker、WASM 与英语数字模型通过 postinstall 从 npm 依赖复制到 public/ocr，运行时显式使用当前静态部署路径。图片不上传，网络仅读取同源静态模型，部署必须包含完整 OCR 目录。

图像定位与识别在 Worker 中执行，OCR 自带后台 worker；无 OffscreenCanvas 时回退逐格 Canvas 并让出事件循环。显示进度与取消入口。模型缓存由 Tesseract 管理，不将原图写入 localStorage。

## 验证与真实样本

自制 `tests/fixtures/board-{8,10,12}.png` 验证自动定位、尺寸判断、模板分类、自动填入、待核对候选持久化及校正；数字 5 验证实际同源 Tesseract；不确定文字验证自动 OCR 启动与取消。Chromium 桌面/手机与 WebKit 手机自动流程均测试。

用户本次两张附件是同一张参考图例，作为负例验证拒绝导入。它们不是游戏棋盘，无法用于报告游戏识别准确率。

后续真实样本可放 `tests/fixtures/real/`，按设备/主题/分辨率配 JSON 记录坐标、尺寸、每格 ground truth，通过 detectGrid/cropPixels/classifyCell/recognizeCells 衡量误检/漏检，再补充授权数字模板与宝石特征。不要以合成图片测试通过率宣称真实游戏识别率。
