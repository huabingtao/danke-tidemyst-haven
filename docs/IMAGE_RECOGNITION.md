# 本地截图识别

## 自动流水线

电脑直接上传；手机选择相册或拍照，另支持拖拽、粘贴及多图 → 原生解码与方向处理 → 大图缩小 → 自动定位和判断 8/10/12 → 切格 → 游戏皮肤特征/字形模板 → 弱数字 OCR 回退 → 可靠结果填入新房间 → 自动关闭进度弹窗并求解。

不提供尺寸、裁剪参数或开始按钮。弱候选保存在 Cell.recognition，真实 observed 保持 unknown，不参与约束。主棋盘点击候选可用宝石和 0–8 弹窗确认。

PNG/JPEG 先读头部尺寸，拒绝超过 2000 万像素；其他格式原生解码后检查像素。最多 30MB、最长边缩放至 1600px，最多 20 张逐张处理。HEIC/HEIF 依赖浏览器解码能力。原生解码处理 EXIF 方向，尚未实现透视校正。

## 真实游戏皮肤通路

旧版仅用整图边缘投影，把本次截图的上方装饰区误当棋盘（原图 y≈139；实际棋盘 y≈988）。旧版青色规则也不适用于金色宝石，并把蓝色盖板纹理混入数字掩码。

`gameBoard.ts` 以最长边 600 的分析分辨率提取青蓝色八连通区域，筛选占图宽至少一半、近正方形且内部不是实心的外框。对 8/10/12 各自检查横纵格子间隙是否稳定比两侧格底更暗，再优化外框内边距。没有使用固定截图坐标、文件名、地图编号或逐格答案。仅有青色外框而缺乏规则间隙时返回低置信度，避免退回装饰区并伪造棋盘。

通过定位证据时 profile=tidemyst，逐格使用以下处理：

- 金黄色饱和前景与蓝色格底共同判断已发现宝石。当前规则分数为 0.97。
- 青蓝盖板判断未翻开，保持 unknown，跳过不必要 OCR。
- 深蓝格底提取居中的中性白色字形，排除黑色描边、背景和外围高光；归一化 20×28。
- 颜色阈值按上端通道分位数校正，兼容已测试的 0.8/1.15 亮度变化。
- 数字匹配保持 Jaccard 重叠度占 75%，双向一像素轮廓容差占 25%，同时检查次佳数字差值。容差用于缩放/JPEG 引起的边缘波动，不取消类别区分门槛。

`gameDigitTemplates.ts` 存放经用户提供截图校准的白色字形掩码：数字 1–4 各选一格，在原始与 1600px 两个栅格尺寸生成。其余同字格子作为样本内验证。生产只包含字形掩码，不包含原图、账号信息、棋盘坐标或答案。所有 0–8 仍使用系统字体模板及 OCR 作为补充；目前没有真实游戏 0、5–8 的独立样本。

重新校准：`node scripts/calibrate-game-glyphs.mjs [image] [labels]`。标注格式见 tests/fixtures/real/tidemyst-8.json。脚本自动定位，并从标注中选择各数字首个例子；不是运行时读取棋盘答案。

## 通用后备与 OCR

未发现游戏外框时保留原 RGB 边缘投影，自动判断普通规则网格 8/10/12；定位低于 0.72 时拒绝导入。通用数字模板由设备系统 Arial/Verdana/Tahoma/Georgia/system-ui 的常规/粗体、30/42/54px 生成。普通青色宝石规则仍只是待核对候选，不会自动声明发现。

游戏通路低于可靠门槛的数字也进入同源 Tesseract 单字符模式，白名单 0–8。独立 OCR 分数小于 0.8 不采纳；模板至少 0.84 且 OCR 至少 0.8 同字一致时使用明确的“一致”评分 0.91；其他 OCR 输出保持自身分数。统一自动填入门槛为 0.9。上述分数是工程决策分数，没有统计准确率含义，也不参与宝石概率求解。

空白或无法解读的白色符号保持未知。没有真实证据时不将暗空白强行填成 0；无法确认的安全状态可用人工录入或旧数据恢复。

## 失败、取消与隐私

定位失败、损坏/超大图片、格式不支持保留原房间并提示重新上传。取消终止 worker/OCR，保留原数据和已经导入的队列房间。OCR 模型加载失败时继续字形匹配，弱结果留在主页面核对。

新房间默认宝石总数按尺寸为 20/30/45。截图目前不读取地图编号及 HUD 总数，主页面可修改；截图 14/20 的 14 颗由棋盘逐格识别得到。正式 solver 校验约束，冲突明确高亮，不输出有效概率。

图片从不上传。OCR worker/WASM/数字模型通过 postinstall 从 npm 依赖复制到 public/ocr，运行时仅读同源静态资源。图像定位与分类在 Worker 执行；无 OffscreenCanvas 时逐格 Canvas 让出事件循环，OCR 使用独立 worker。原图不写 localStorage，也不纳入 dist。

## 验证范围

本次真实 JPEG（1170×2532）人工标注为 14 宝石、17 数字、33 未翻开格。原图逐格 64/64 一致，自动返回棋盘且推理无冲突，已发现 14 / 剩余 6。Chromium 桌面/手机及 WebKit 手机均验证完整流程。

另对同一图生成 1600px/JPEG70、约1013px/JPEG55、亮度0.8/JPEG75、亮度1.15/JPEG75 四种变体，在三个浏览器配置逐格验证。纯函数测试覆盖游戏定位、三种尺寸的独立合成皮肤网格、金色/盖板/数字分类、无间隙外框拒绝及未知符号降级。原有合成通用棋盘、实际数字 5 OCR、取消、多图、图例拒绝和异常输入回归保留。

这是一张真实样本及其变体的验收，不是独立真实测试集，不报告通用识别成功率。真实 10×10/12×12、其他皮肤、真实 0/5–8、倾斜拍照、严重模糊及微信真机仍需更多素材验证。
